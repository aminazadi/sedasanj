# Seda Sanj Issabel Module 1.6.0 — beta

این بسته برای ایزابل ۴ و ۵ طراحی شده است. وضعیت نصب، ضبط و بازگردانی روی PBX واقعی هنوز **⚠ نیازمند تأیید آزمایشگاهی** است. موفقیت تست‌های خودکار، تأیید نصب عملیاتی نیست.

## نصب

1. از تنظیمات PBX و ضبط‌ها بکاپ بگیرید. بسته `recuploader-1.6.0.tgz` را از مدیر ماژول‌های **PBX Configuration** بارگذاری و نصب کنید؛ ZIP مخصوص FreePBX را بارگذاری نکنید.
2. PHP وب ایزابل را حفظ کنید. برای ایزابل ۴ یک PHP CLI مستقل حداقل 7.4 نصب کنید. افزونه‌های `curl`, `json`, `zlib`, `pdo_mysql`, `pdo_sqlite`, `simplexml`, `ctype` و ابزار `lsof` لازم‌اند. برای به‌روزرسانی امضاشده `sodium` نیز لازم است.
3. ضبط PBX باید `wav` باشد. اگر فرمان پس از ضبط دیگری دارید، قبل از فعال‌سازی تداخل آن را برطرف کنید؛ این نسخه فرمان قبلی را جایگزین نمی‌کند.
4. فعال‌سازی را با دسترسی root و مسیر PHP مستقل اجرا کنید:

```bash
bash /var/www/html/admin/modules/recuploader/activate.sh /opt/remi/php74/root/usr/bin/php
```

در ایزابل ۵، اگر PHP CLI سیستم 7.4 یا جدیدتر است، مسیر `/usr/bin/php` را بدهید. مسیر سفارشی وب‌روت را در فرمان جایگزین کنید. فایل اجرایی PHP و پوشه‌های والد آن باید متعلق به root و غیرقابل‌نوشتن برای گروه/دیگران باشند. نصب‌کننده هیچ مخزن بسته‌ای فعال نمی‌کند و PHP سیستم را عوض نمی‌کند.

نصب SSH همان فعال‌ساز را اجرا می‌کند:

```bash
bash /path/to/recuploader/install.sh /usr/bin/php
```

5. صفحه «Seda Sanj» را باز کنید، فایل تنظیمات مخصوص ایزابل را وارد و پیش‌نمایش ماسک‌شده را بررسی کنید. پس از تأیید آنلاین، تنظیمات را اعمال کنید.
6. بررسی سلامت را اجرا و یک تماس آزمایشی برقرار کنید. فایل اصلی باید در گزارش CDR ایزابل قابل پخش و همان تماس در صداسنج قابل مشاهده باشد.

## رفتار و تنظیمات

- موتور مشترک در مخزن `module-engine/` است؛ هر بسته نسخه کامل و مستقل آن را دارد. لایه وب ایزابل PHP 5.4 را هدف می‌گیرد و موتور نیازمند PHP CLI 7.4+ است.
- callback تولید dialplan با اولویت 900 فقط فرمان‌های شناخته‌شده MixMonitor را تغییر می‌دهد. فایل core یا callrecording ایزابل ویرایش نمی‌شود.
- فرمان post-recording متعارض یا ساختار ناشناخته با `SS-HOOK-1010` متوقف می‌شود. dialplan عادی PBX حفظ می‌شود.
- فایل اصلی ضبط حفظ می‌شود. کانال‌های موقت به فضای کاری صداسنج کپی می‌شوند؛ پس از آماده‌سازی، فقط legهای ساخته‌شده برای صداسنج پاک می‌شوند.
- بازیابی از زمان اولین فعال‌سازی آغاز می‌شود؛ ضبط‌های تاریخی خودکار وارد نمی‌شوند. فایل باز با `lsof` شناسایی و برای بررسی بعدی نگه داشته می‌شود.
- نبود ستون‌های لازم CDR در سلامت نمایش داده می‌شود. تشخیص داخلی پاسخ‌دهنده از `uniqueid` استفاده می‌کند؛ تماس ازدست‌رفته به `linkedid` نیاز دارد و روی ساختار ناکافی قابل فعال‌سازی نیست.
- مدل‌های پردازش از تنظیمات کلید API در پنل صداسنج انتخاب می‌شوند؛ ماژول تنظیم تکراری برای مدل ندارد.
- تغییر PHP موتور از فرمان فعال‌سازی صفحه تنظیمات اعمال می‌شود. تغییر توسط مدیر سیستم انجام می‌شود تا مسیر قابل‌اجرای ریشه از درخواست وب تعیین نشود.
- هیچ محدودیت SELinux غیرفعال نمی‌شود. وضعیت آن در سلامت نمایش داده می‌شود؛ مجوز یا policy لازم باید روی همان سیستم بررسی شود.
- صفحه مدیریت فقط با نشست معتبر و دسترسی بخش `recuploader` قابل استفاده است؛ درخواست‌های عملیات به CSRF معتبر نیاز دارند.

## انتشار و به‌روزرسانی

```bash
scripts/test-issabel-module.sh 5.6 7.4 8.2
scripts/test-freepbx-module.sh 7.4 8.2
scripts/build-issabel-module-release.sh
```

خروجی محلی در `deliverables/` ساخته و وارد Git نمی‌شود. محصول در سامانه انتشار `issabel-recuploader` است؛ بارگذاری، کلید عمومی سرور را داخل بسته قرار می‌دهد و digest و manifest را امضا می‌کند. بسته محلی پیش از انتشار، امضای سرور ندارد؛ فقط برای آزمایش دستی استفاده شود.

بسته باید در کانال beta منتشر شود. انتقال به stable تا تکمیل ماتریس آزمایش مجاز نیست؛ مدیر ارشد باید نتایج نصب، تماس و بازگردانی همان بسته را در صفحه نسخه ثبت و با رمز/عامل دوم تأیید کند. کنترل محصول، نوع آرشیو، نسخه، PHP، بازه ایزابل، انقضا و امضا پیش از استخراج و نصب دوباره انجام می‌شود. updater از نسخه root-owned ابزارها و کلید اعتماد استفاده می‌کند.

## بکاپ، بازگردانی و حذف

پیش از تغییرات، بکاپ root-only به همراه manifest و SHA-256 در `/var/backups/sedasanj-recuploader/issabel-*` ساخته و بررسی می‌شود. بکاپ حاوی تنظیمات محرمانه است؛ آن را در مسیر وب قرار ندهید. صف و ضبط اصلی هنگام ارتقا جابه‌جا نمی‌شوند.

شکست فعال‌سازی موجب بازگردانی خودکار فایل‌های نصب می‌شود. برای بازگردانی دستی، از بسته استخراج‌شده و بکاپ تأییدشده استفاده کنید:

```bash
/path/to/php /path/to/recuploader/bin/provision.php --restore /var/backups/sedasanj-recuploader/issabel-TIMESTAMP
```

این فرمان ابتدا از وضعیت فعلی بکاپ می‌گیرد. بعد از بازگردانی، یک تماس آزمایشی لازم است.

```bash
bash /var/www/html/admin/modules/recuploader/uninstall.sh
```

حذف، سرویس و اتصال ضبط را برمی‌دارد؛ تنظیمات، صف، فایل‌ها و بکاپ‌ها حفظ می‌شوند. برای حذف داده‌ها، ابتدا آن‌ها را خارج از PBX آرشیو کنید؛ حذف خودکار داده‌ها ارائه نمی‌شود.
