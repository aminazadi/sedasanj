# Changelog — Jalase Negar

## 2026-11-11 — AMINAZADI

- Fixed the macOS build failing on another Mac and the SedaSanj connection not being saved there: the app was signed by Xcode with a device-bound Apple Development profile and the `keychain-access-groups` entitlement, which another Mac refuses (OSStatus -34018 or killed at launch). The token now uses the legacy keychain (`MacOsOptions(usesDataProtectionKeychain: false)`), the entitlement is removed, and `scripts/build-jalase-negar-release.sh macos` drops the provisioning profile and re-signs ad-hoc (first launch: right-click > Open). Windows uses the same Dart code (Credential Manager for the token). NOT run on a second Mac or on a Windows PC.
- Changed the DMG background (logo, name, install guide, SedaSanj wordmark and sedasanj.ir) and the Windows installer images (logo, name, SedaSanj wordmark and sedasanj.ir; the old tagline and line removed). The wizard BMPs were top-down 32-bit files that Inno Setup shows flipped; they are now standard bottom-up 24-bit.

- Added recording the phone's own microphone together with a USB receiver on Android 10+ («همهٔ میکروفون‌های متصل»), so every microphone picks up sound at once: the receiver's channels come first and the phone's microphone is the last channel (one channel, VOICE_RECOGNITION source); each has its own waveform, mute and person button, and the mono mix used for the text takes the loudest microphone per 20 ms as before. A second AudioRecord is opened on the built-in microphone beside the USB one; the USB receiver is the clock and the phone's stream is kept in step by a small queue (`StreamJoiner`: 40 ms cushion, oldest audio dropped above 150 ms, silence when late). If the phone refuses the second stream, or opening it moves the USB stream to another device, the phone's microphone is closed and the receiver is recorded alone with a Persian note; the channel count stays the same. Android's audio documentation says different streams may use different devices but leaves it to each phone's audio hardware, so this is NOT guaranteed on every phone. Kotlin unit tests (13, four new for the joiner) and `flutter test` pass; NOT run on any phone, so whether the reporter's phone allows both streams, the real delay between the two microphones (a voice heard by both within 9 dB is summed with that delay and may sound slightly hollow) and long-recording drift are unverified. iOS still records the USB input only (one input route at a time).

- Fixed the Android capture of an external USB microphone receiver (reported: Hollyland Lark M2 shows two channels with one silent, and the sound is loud and unintelligible). Changes: the stream is asked for at 16 kHz directly, falling back to the device rate decimated with a windowed-sinc low-pass (the old averaging/linear resampler aliased; tests show a 12 kHz tone is removed and levels stay within 2%); one or two channels use ordinary positional masks and only more than two use an index mask (real channel count from the index masks first); the audio source is UNPROCESSED or VOICE_RECOGNITION, never MIC, and the system's gain control, noise suppression and echo cancellation are switched off on the session; after starting, the actual route is checked and the recording is refused (new code `JN-REC-0007`) if it is not the chosen USB device, and an unplug or route change during recording now stops it with the same code instead of recording silence; opening runs off the UI thread. New diagnostics in logcat under tag `JN-REC` (device capabilities, source, route, effects, per-channel peak/RMS/clip count/correlation every 5 s). In Dart: `ChannelProbe` flags a channel that is digital silence or a copy of another (a mono receiver duplicating its mix) after 2 s, leaves it out of the mix and shows a Persian note under the live text; the mix uses a soft limiter instead of a hard clamp when two channels sum above −3 dBFS; the waveform is on a dB scale (−60..0 dBFS, speech mid-height) instead of `rms*5`, which filled the bar at −14 dBFS and made a normal input look over-sensitive. Verified: `flutter test` (454 pass, 4 skipped), nine new Kotlin unit tests (`CaptureMathTest`: channel count, rates, resampler level/alias/channel separation, stats) pass, `flutter analyze` shows only 3 older issues in files not touched. NOT verified: any real phone or receiver, so whether the Lark M2 really sends one mixed channel (its manual says the phone version is mono-only), whether the second channel was the zero-filled one, and whether the loudness came from the source/effects or the resampler, all still need the logcat of one 20-second recording. Capturing the phone's own microphones together with the USB input is not done: Android gives no guarantee for two physical devices at once.

- Added optional `sha256` (per file) and `license` (per model) fields to the model catalog and filled them from `docs/asr-benchmark.md` (9 weight files; the CED class-label list has none) and from licences the catalog already stated (CAM++ Apache-2.0, pyannote MIT). They are recorded only: the downloader does not check them, so downloads behave exactly as before, and the copies hosted on sedasanj.ir were not compared with the benchmark files. Catalog tests pass (11). Also found, not changed: the GTCRN entry says about 1.7 MB (an estimate) while the benchmark file is 535,638 bytes.
- Changed the bottom bar: the record diamond sits 16 px lower and the notch it sits in is cut 16 px deeper (the gap between them is unchanged). Not seen on a screen yet.
- Fixed the «نام‌گذاری» button of «نام‌گذاری صداهای ناشناس» being disabled for a voice with under 4 s of speech (shown as «گفتار کم»). It is always enabled now: with too little clean speech a new person is still created and the voice's lines are named, only without a voiceprint (added later from the person's page). Analyzer/tests below; not tried on a screen.

- Added a speaker evaluation toolchain, with no change to app behaviour, models or defaults: `sedasanj/scripts/speaker_eval.py` (DER, naming accuracy, wrong-name rate, paired bootstrap compare, draft labels; 13 tests in `sedasanj/tests/test_speaker_eval.py`), `test/bench/bench_speaker_test.dart` (real diarizer and embedder on a labelled set, post-recording path only) and the set layout in `sedasanj/test_data/speaker_eval/`. Run end to end once on a synthetic two-speaker set built from the two existing clips (diarization about 10 s for 120 s of audio on this Mac, 2 threads); that proves the tool works, not the app's accuracy. NOT run: any phone, any real multi-speaker Persian meeting (none exists yet), any other speaker model (none downloaded; the survey in `docs/speaker-model-evaluation.md` is partial and marks unconfirmed licences).
