# انتخاب خودکار ابزارهای دستیار

برای انتخاب خودکار، ابزار دستی انتخاب نکنید و درخواست را روشن بنویسید؛ مثلاً «آمار تماس‌های هفته گذشته و فایل اکسل آن را بده». دستیار می‌تواند در فهرست قابلیت‌های فعال با عبارت فارسی یا انگلیسی جست‌وجو کند و یک یا چند ابزار مناسب را برای اجرا انتخاب کند. ابزارهای واقعی اجراشده در خط زمان پیام نمایش داده می‌شوند.

جست‌وجوی فهرست فقط توضیح ابزار و قرارداد ورودی آن را برمی‌گرداند و به داده‌های سازمان دسترسی ندارد. دریافت داده و ساخت فایل همچنان از مسیر ابزارهای دارای کنترل سازمان، کاربر و اپراتور انجام می‌شود. کاربر ابزار انتخاب نمی‌کند و انتخاب دستی ابزار در رابط حذف شده است؛ ابزار فایل همیشه فعال است و حالت آموزش هیچ ابزاری اجرا نمی‌کند.

## اجرای ابزارها با webhook امضاشده

دستیار ابزار را مستقیم صدا نمی‌زند؛ یک POST امضاشده به `/v1/internal/tools/{name}` می‌فرستد. امضا HMAC-SHA256 روی زمان، nonce، نام ابزار و بدنه است و کلید آن از `JWT_SECRET` مشتق می‌شود، پس تنظیم جدیدی لازم نیست. درخواست تا ۶۰ ثانیه معتبر است، nonce فقط یک بار قبول می‌شود و نتیجه هر `tool_call_id` تا ۱۰ دقیقه ذخیره می‌شود تا تلاش دوباره فایل تکراری نسازد. هویت کاربر از بدنه امضاشده بازسازی می‌شود و ابزار در دامنه دیتابیس همان سازمان اجرا می‌شود.

متغیر `TOOL_GATEWAY_URL` (در compose برابر `http://api:8000`) نشانی داخلی API است. اگر خالی باشد یا API در دسترس نباشد، همان اجراکننده داخل پردازش اجرا می‌شود.

در تنظیمات ادمین، بخش دستیار، «مراحل جست‌وجوی خودکار ابزار» از صفر تا دو قابل تنظیم است. مقدار پیش‌فرض دو است؛ صفر جست‌وجوی فهرست را حذف می‌کند و انتخاب مستقیم ابزار باقی می‌ماند. سقف تعداد ابزارهای واقعی هر پیام نیز با تنظیم موجود کنترل می‌شود. هیچ جست‌وجویی ابزار جدیدی را فعال نمی‌کند.

برای خروجی فایل باید دسته داده و قالب روشن باشد. اگر این اطلاعات در سابقه گفتگو مشخص باشند، دستیار می‌تواند درخواست «انجامش بده» را با همان سابقه اجرا کند. در صورت ابهام، باید سؤال روشن‌کننده بپرسد. ورودی نامعتبر ابزار یک بار به‌صورت محدود برای اصلاح برنامه به مدل برمی‌گردد؛ اطلاعات نامشخص با مقدار ساختگی پر نمی‌شوند. ردشدن قرارداد Native در سرویس‌های ناسازگار می‌تواند از مسیر برنامه JSON معتبر ادامه پیدا کند.

## رفع خطا

- `assistant_tool_plan_invalid`: نوع داده، قالب خروجی و بازه را دقیق‌تر بنویسید؛ اگر ادامه داشت، مدیر سامانه مدل و حالت ابزار را بررسی کند.
- `assistant_export_unavailable`: مدیر سامانه باید migration `0061_assistant_exports` را روی دیتابیس لازم اعمال یا دسترسی مخزن فایل را اصلاح کند. پس از رفع مشکل، خروجی جدید بخواهید.

با اجرای `python scripts/seed_help_articles.py` پیش‌نویس راهنمای این قابلیت و مقاله‌های کدهای بالا بدون بازنویسی مقاله‌های موجود ساخته می‌شوند. آن‌ها را در مرکز راهنما بررسی و منتشر کنید.
