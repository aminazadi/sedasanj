# راهنمای درگاه‌های پرداخت (زرین‌پال، زیبال، سپ، به‌پرداخت ملت)

طراحی و دلیل تصمیم‌ها: `docs/payment-gateways-plan.md`. این سند برای راه‌اندازی و عیب‌یابی است.

## راه‌اندازی

1. در `deploy/.env` مقدار `PLATFORM_SECRETS_KEY` را بسازید (بدون آن ذخیره‌ی اطلاعات درگاه رد می‌شود):

   ```bash
   python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
   ```

2. `PUBLIC_BASE_URL` باید آدرس عمومی HTTPS سرویس باشد؛ آدرس بازگشت هر درگاه
   `https://<دامنه>/v1/payments/<zarinpal|zibal|saman|behpardakht>/callback` است و باید نزد بانک/درگاه ثبت شود.
3. IP خروجی سرور API را در پنل هر درگاه ثبت کنید (بدون آن: زرین‌پال ‎-۱۰، به‌پرداخت ۴۲۱، سپ خطای کد ۸).
4. پنل ادمین ← «درگاه‌های پرداخت»: اطلاعات را وارد، «تست اتصال» را بزنید و سپس «نمایش به عنوان روش پرداخت» را روشن کنید.
   فقط درگاه‌های فعال و کامل‌شده به مشتری نشان داده می‌شوند.

| درگاه | اطلاعات لازم | حالت آزمایشی |
|---|---|---|
| زرین‌پال | Merchant ID (۳۶ نویسه) | `sandbox` (هر UUID نسخه ۴) |
| زیبال | Merchant ID | merchant برابر `zibal` |
| سپ | شماره ترمینال | ندارد |
| به‌پرداخت | ترمینال، نام کاربری، رمز | ندارد |

پیکربندی قدیمی زرین‌پال (`ZARINPAL_MERCHANT_ID` / `commerce.*`) تا اولین ذخیره از صفحه‌ی جدید همچنان کار می‌کند.

## مسیر یک پرداخت

1. مشتری سفارش را می‌سازد (شارژ: `دقیقه × نرخ دقیقه‌ی پلن`، قیمت را سرور محاسبه می‌کند) و روش پرداخت را انتخاب می‌کند.
2. `POST /v1/orders/{id}/pay` توکن بانک را می‌گیرد؛ مرورگر با GET یا فرم POST به بانک می‌رود.
3. بانک به `/v1/payments/<درگاه>/callback` برمی‌گردد. سرور شناسه‌ی پرداخت، شماره‌ی تلاش و مبلغ را تطبیق می‌دهد، وضعیت را ذخیره
   (`pending_verification`) و بعد از بانک وریفای می‌کند.
4. پس از وریفای موفق و تطبیق مبلغ، سفارش `paid` می‌شود، دقیقه‌ها به `credit_grants` و دفتر کل (`credit_purchase`) اضافه و فاکتور صادر می‌شود.
5. فقط به‌پرداخت: پس از تکمیل سفارش، `bpSettleRequest` (ستل) انجام می‌شود؛ خطا تا موفقیت هر دقیقه تکرار می‌شود.
6. اگر مرورگر هرگز برنگشت یا وریفای قطع شد، جارو (`reconciler_cron`) پرداخت‌های معلق را پیگیری می‌کند و بعد از ۲ ساعت بی‌پاسخ، تلاش `expired` می‌شود.

## وضعیت‌های تلاش پرداخت

`redirected` ← مرورگر به بانک رفته · `pending_verification` ← بازگشت ثبت شد، وریفای منتظر است · `verified` ← پرداخت تأیید و اعمال شد
(برای ملت «ستل‌نشده» تا ثبت ستل) · `failed` · `canceled` (انصراف کاربر) · `expired` · `superseded` (سفارش با تلاش دیگری پرداخت شده؛ بانک مبلغ این تلاش را خودکار برمی‌گرداند).

## عیب‌یابی

| نشانه | علت محتمل | اقدام |
|---|---|---|
| «تست اتصال» کد ‎-۱۰ / ۴۲۱ / ۸ | IP سرور نزد درگاه ثبت نیست | IP خروجی را در پنل درگاه ثبت کنید |
| زرین‌پال ‎-۱۴ / به‌پرداخت ۶۲ | دامنه‌ی callback با دامنه‌ی ثبت‌شده نمی‌خواند | `PUBLIC_BASE_URL` و دامنه‌ی ثبت‌شده را یکی کنید |
| پرداخت «نیازمند بررسی» | قطع ارتباط هنگام وریفای | منتظر جارو (۱ دقیقه) بمانید یا «تطبیق امن» را بزنید |
| `failure_code=amount_mismatch` | مبلغ بانک با سفارش نمی‌خواند | تلاش رد شد و برگشت بانکی زده شد؛ مبلغ را در پنل بانک بررسی کنید |
| «ستل‌نشده» در پرداخت‌های ملت | خطای ستل | جارو تکرار می‌کند؛ بعد از ۴۰ تلاش دستی «تطبیق امن» بزنید و با بانک تماس بگیرید |
| مشتری می‌گوید پول کسر شد ولی اعتبار نیامد | پرداخت معلق یا بازگشت ثبت‌نشده | در «سفارش و پرداخت ← پرداخت‌ها» تلاش را پیدا کنید و «تطبیق امن» بزنید |

کدهای خطای API: `payment_method_unavailable` (۴۰۹: درگاه فعال/متناسب با مبلغ نیست؛ درگاه دیگر را انتخاب کنید یا درگاه را فعال کنید)،
`payment_gateway_unavailable` (۵۰۲، قابل تکرار: بانک در دسترس نیست؛ کمی بعد دوباره تلاش کنید).

## تأیید آزمایشگاهی (قبل از فعال‌سازی عملیاتی)

با ترمینال آزمایشی هر بانک این موارد را یک‌بار اجرا کنید: پرداخت موفق، انصراف، قطع نت هنگام بازگشت، پرداخت تکراری، برگشت (`reverse`)
و (ملت) ستل. موارد «⚠» در `payment-gateways-plan.md` بخش ۷ را ثبت کنید.
