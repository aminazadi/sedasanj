# راهنمای راه‌اندازی انتشار مدل

## نشانه‌ها

اگر API هنگام راه‌اندازی برای `ml_publisher_tenant_id` خطای `uuid_parsing` می‌دهد و پردازش‌های آن پیوسته بسته می‌شوند، مقدار `ML_PUBLISHER_TENANT_ID` را در تنظیمات استقرار بررسی کنید.

## علت

نسخه‌های پیش از این اصلاح، مقدار خالی متغیر اختیاری انتشار مدل را UUID نامعتبر تشخیص می‌دادند. فایل نمونه و Compose این متغیر را به‌صورت پیش‌فرض خالی می‌فرستند.

## رفع مشکل

1. نسخه دارای اصلاح را دریافت و تصویر API را دوباره بسازید؛ سپس کانتینر API را با تصویر جدید ایجاد کنید.
2. اگر انتشار مدل لازم نیست، `ML_PUBLISHER_TENANT_ID` را خالی بگذارید. مقدار خالی یا فقط فاصله، انتشار را غیرفعال می‌کند و مانع راه‌اندازی API نمی‌شود.
3. برای فعال‌سازی انتشار، UUID سازمان پلتفرم را در این متغیر قرار دهید و کانتینر API را دوباره ایجاد کنید. کلید انتشار را با `scripts/create_ml_publisher_key.py` برای همان سازمان و با محدودیت آدرس سرور GPU بسازید. کلید را در گزارش یا پیام پشتیبانی درج نکنید.
4. مقدار غیرخالی و نامعتبر همچنان رد می‌شود؛ آن را با UUID معتبر جایگزین کنید یا برای غیرفعال‌سازی انتشار، مقدار را خالی کنید.

## تأیید

پس از ایجاد مجدد کانتینر، نبود خطای اعتبارسنجی این متغیر را در گزارش راه‌اندازی بررسی کنید. وقتی متغیر خالی است، درخواست انتشار با کلید دارای مجوز `ml:publish` باید با وضعیت `403` و کد `ml_publish_forbidden` رد شود. این کد برای کلید یا سازمان اشتباه و نبود محدودیت IP نیز به کار می‌رود؛ تنظیمات سازمان، مجوز و آدرس‌های مجاز را بررسی کنید.

## پیشگیری

برای غیرفعال‌سازی، مقدار را خالی بگذارید؛ رشته‌های `null` و `None` جایگزین مقدار خالی نیستند. پیش از فعال‌سازی، شناسه سازمان و محدودیت IP کلید انتشار را بررسی کنید.
