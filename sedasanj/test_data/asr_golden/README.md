# مجموعهٔ طلایی ASR (Golden set)

این پوشه فقط راهنما و نمونهٔ manifest را نگه می‌دارد. **صوت، متن مرجع واقعی و خروجی سیستم‌ها هرگز commit نمی‌شوند** (در `.gitignore` هستند): ممکن است داده‌ی مشتری باشند.

## ساختار محلی

```
test_data/asr_golden/
  manifest.json            # شامل clips (از manifest.example.json بسازید)
  audio/<id>.wav           # PCM16، mono، 16kHz (یا 8kHz برای کلیپ تلفنی)
  hypotheses/<system>.json # {"<id>": "متن"}
```

## معیار انتخاب کلیپ (۲۰ تا ۴۰ کلیپ)

- هر کلیپ ۳۰ تا ۱۲۰ ثانیه؛ فقط صوتی که مجوز استفاده دارد؛ نام، شماره و اطلاعات شخصی حذف یا ناشناس شده باشد.
- پوشش `tags`: `meeting` (جلسه)، `phone-8k` (تلفنی)، `quiet` (گفتار آرام یا دور از میکروفن)، `noisy` (پرنویز)، `clean`، `overlap` (هم‌پوشانی گوینده)، `numbers` (عدد و تاریخ)، `long` (بیش از ۱۰ دقیقه، حداقل ۲ کلیپ).
- متن مرجع را انسان بنویسد؛ خروجی خود ASR را بدون بازبینی مرجع نکنید. اگر پیش‌نویسِ ساخته‌شده از خروجی مدل را اصلاح می‌کنید، با صوت یک‌به‌یک گوش کنید و حتی جاهایی را که درست به نظر می‌رسند کنترل کنید: خطایی که پیش‌نویس و مدل هر دو دارند و از قلم بیفتد در امتیاز دیده نمی‌شود.

### نوشتن مرجع

امتیازدهی (`normalize_for_scoring` در `scripts/asr_eval.py`) علائم نگارشی، اعراب و تشدید، تفاوت «ي/ی» و «ك/ک»، حروف بزرگ و کوچک و تفاوت ارقام فارسی و انگلیسی را نادیده می‌گیرد، و فاصلهٔ مجازی را با فاصله یکی می‌داند. پس:

- هر خط یک جمله؛ برچسب زمان ابتدای خط (`[01:21]`) را می‌توانید نگه دارید یا پاک کنید.
- «می‌روم» و «می روم» یکی‌اند، ولی «میروم» (بدون فاصله و بدون فاصلهٔ مجازی) کلمهٔ دیگری حساب می‌شود.
- عدد را همان‌طور که گفته شده با حروف بنویسید («بیست و پنج»)؛ «۲۵» و «بیست و پنج» یکی حساب نمی‌شوند.
- واژهٔ انگلیسی را با املای فارسیِ رایج بنویسید (مثل «دیپلوی»)؛ املای دیگری از همان واژه خطا حساب می‌شود، پس این بخش کمی ناعادلانه است و باید در تفسیر نتیجه مد نظر باشد.
- جایی را که واقعاً نمی‌شود فهمید، با «؟؟؟» بگذارید و تعدادش را یادداشت کنید؛ علامت سؤال حذف می‌شود و کلمه‌ای در مرجع نمی‌ماند، پس هر کلمه‌ای که سیستم همان‌جا بنویسد «اضافه» حساب می‌شود.

## گرفتن خروجی هر سیستم

1. **Baseline A: سرور (CPU، INT8).** همه کلیپ‌ها را به aiservice بدهید و فقط متن را ذخیره کنید:
   ```bash
   curl -sS -H "Authorization: Bearer $ASR_API_KEY" \
     -F model=shenava-koochik-v1-5-rnnt -F language=fa -F ensure_timestamps=true \
     -F response_format=verbose_json -F file=@audio/clip01.wav \
     "$ASR_URL/v1/audio/transcriptions"
   ```
   پاسخ `202` است؛ نتیجه را از `Location: /v1/tasks/{id}` و `/result` بگیرید و `text` را در `hypotheses/server-cpu-int8.json` بگذارید. کلید API را در shell history یا گزارش ننویسید.
2. **Baseline B: اپ فعلی.** خروجی رونویسی لوکال جلسه‌نگار را برای همان کلیپ‌ها به `hypotheses/app-current.json` ببرید (ابزار export در فاز ۴ ساخته می‌شود؛ تا آن موقع دستی از جزئیات جلسه).
3. نام سیستم = نام فایل بدون پسوند.

## اجرا

```bash
cd sedasanj
python scripts/asr_eval.py score test_data/asr_golden/manifest.json \
  test_data/asr_golden/hypotheses/server-cpu-int8.json \
  test_data/asr_golden/hypotheses/app-current.json
python scripts/asr_eval.py compare test_data/asr_golden/manifest.json \
  test_data/asr_golden/hypotheses/server-cpu-int8.json \
  test_data/asr_golden/hypotheses/app-candidate.json --max-delta 0.02
```

اگر برای کلیپی خروجی نباشد اسکریپت خطا می‌دهد (WER را با کلیپ جاافتاده مقایسه نمی‌کند). آستانهٔ نهایی ۲٪ پس از ثبت Baseline تأیید می‌شود.

## برچسب‌های جدید و ابزار فاز ۰

- برچسب‌های تازه: `codeswitch` (واژهٔ انگلیسی میان فارسی)، `lavalier`، `table`، `rev` (پژواک)، `snr-N` (مثلاً `snr-10`)، `ovl-N` (مثلاً `ovl-20`)، `quiet-N` (سطح صدا N دسی‌بل پایین‌تر، مثلاً `quiet-30`)، `noise-only` (کلیپ فقط-نویز)، و `non-speech`/`silence` برای کلیپ بدون گفتار با `reference` خالی (هر واژهٔ خروجی روی آن «هالوسینیشن» شمرده می‌شود و در WER نمی‌آید).
- مرجع چندنفره برای cpWER: به‌جای رشته، فهرست `[{"speaker": "A", "text": "..."}, ...]` یا شیء `{"A": "..."}` بنویسید؛ فرضیه هم می‌تواند همین قالب را داشته باشد (رشتهٔ ساده = یک گوینده). حداکثر ۸ گوینده در هر کلیپ.
- زمان‌بندی اختیاری: کنار `hypotheses/<system>.json` فایل `<system>.latency.json` با `{"<id>": {"audio_seconds": 61.2, "processing_seconds": 24.0, "final_latency_seconds": 1.1}}` بگذارید؛ باید همهٔ کلیپ‌ها را بپوشاند.
- `compare` حالا آستانهٔ جدا دارد: `--max-clean-delta` (پیش‌فرض ۰: پسرفت روی `clean` ممنوع) و `--noisy-min-gain` (بهبود نسبی لازم روی `noisy` با WER و `overlap` با cpWER؛ پیش‌فرض ۰ یعنی بدتر نشود).

### داده سنتزی

```bash
pip install numpy soundfile
python scripts/asr_augment.py test_data/asr_golden/manifest.json ~/asr_golden_aug \
  --audio-root test_data/asr_golden --noise noise.wav --seed 1234
python scripts/asr_eval.py score ~/asr_golden_aug/manifest.json hypotheses/app-current-aug.json
```

خروجی را خارج از مخزن (یا مسیر gitignore) بگذارید؛ صوت و manifest تولیدی commit نمی‌شود. بدون `--noise` نویز صورتی مصنوعی استفاده می‌شود که آسان‌تر از نویز واقعی است؛ مجوز مجموعهٔ نویز را پیش از استفاده تأیید کنید. هم‌پوشانی با کلیپ بعدیِ manifest (گوینده‌ای متفاوت فرض می‌شود) ساخته می‌شود و مرجعش گوینده‌دار است.

با `--keep-originals` کلیپ‌های اصلی هم بدون تغییر (همان شناسه، مرجع و برچسب) در خروجی کپی می‌شوند تا یک manifest هم مجموعهٔ تمیز را داشته باشد و هم واریانت‌هایش را؛ آن‌وقت `asr_eval.py compare` در یک اجرا هم `clean` و هم `noisy` را می‌سنجد.

دو واریانت دیگر به‌صورت پیش‌فرض ساخته می‌شوند:

- **کم‌صدا** (`--quiet 20 30`): همان کلیپ با سطح ۲۰ و ۳۰ دسی‌بل پایین‌تر و بدون نویز؛ نشان می‌دهد کلمه پیش از رسیدن به مدل (VAD، نرمال‌سازی سطح) گم می‌شود یا نه. برچسب `clean` در آن حذف می‌شود چون سطح، سطح ضبط‌شده نیست. با `--quiet` بدون مقدار ساخته نمی‌شود.
- **فقط-نویز** (`--noise-only 30`، شناسه `noise-only`): ۳۰ ثانیه نویز بدون گفتار، به بلندی نویز در واریانت‌های `snr-5` (با `--noise-only-snr` عوض می‌شود). هر واژه‌ای که سیستم روی آن بنویسد ساختگی است و به‌عنوان هالوسینیشن گزارش می‌شود. با نویز صورتی مصنوعی صفر بودنش چیز زیادی ثابت نمی‌کند؛ برای نتیجهٔ معنادار ۳۰ تا ۶۰ ثانیه ضبط نویز واقعی اتاق را با `--noise` بدهید. با `--noise-only 0` ساخته نمی‌شود.
