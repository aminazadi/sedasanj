# مدل‌های کم‌فشار CPU برای پردازش متن فارسی

## خلاصه اجرایی

برای این سرویس، بهترین سبد آزمایش سه‌مدلی به‌ترتیب زیر است:

1. **Gemma 3 4B IT — Q4_K_M**: انتخاب اول برای تعادل کیفیت، اندازه و پشتیبانی چندزبانه؛ مناسب اصلاح متن و صورت‌جلسه.
2. **Qwen3 4B — Q4_K_M**: انتخاب دوم و احتمالاً بهترین رقیب عمومی؛ باید حالت reasoning با `/no_think` خاموش شود تا زمان CPU و خروجی اضافی هدر نرود.
3. **Qwen2.5 3B Instruct — Q4_K_M**: انتخاب کم‌فشار برای baseline سریع؛ کیفیت آن در فارسی باید با داده واقعی سنجیده شود، ولی فایل فقط 2.10 GB است.

اگر کیفیت فارسی بر مصرف منابع اولویت دارد، **Aya Expanse 8B Q4_K_M** نیز ارزش آزمایش دارد، زیرا سازنده صریحاً فارسی را یکی از 23 زبان هدف اعلام کرده است. بااین‌حال، فایل آن 5.06 GB است، سرعت CPU آن در رده Dorna 8B خواهد بود و مجوزش برای استفاده تجاری مناسب نیست. بنابراین Aya یک گزینه آزمایشی/پژوهشی است، نه انتخاب پیش‌فرض تولید.

هیچ بنچمارک عمومی معتبری دقیقاً «اصلاح خروجی ASR فارسی و ساخت صورت‌جلسه روی CPU، با همین quant و همین prompt» را اندازه‌گیری نکرده است. رتبه‌بندی نهایی باید با corpus واقعی خود سرویس انجام شود. شواهد عمومی فقط shortlist را تعیین می‌کنند.

## محدودیت‌های فنی همین پروژه

بررسی کد فعلی نشان می‌دهد مدل متنی با `llama-cpp-python==0.3.16` و `n_gpu_layers=0` اجرا می‌شود، cache فقط یک LLM را نگه می‌دارد و context پیش‌فرض `12,288` توکن است. فرم پنل برای هر مدل سفارشی فقط یک فایل GGUF می‌پذیرد. در نتیجه:

- مدل‌های تک‌فایل مستقیماً قابل ثبت‌اند.
- Qwen2.5 7B رسمی در Q4_K_M دو فایل دارد و در وضعیت فعلی پنل، انتخاب مناسبی برای ثبت مستقیم نیست.
- RAM فقط برابر اندازه GGUF نیست. وزن‌ها تقریباً هم‌اندازه فایل حافظه می‌گیرند، اما KV cache و buffer محاسباتی نیز اضافه می‌شوند؛ اندازه KV cache با context رشد می‌کند.[^1]
- context برابر 12K برای ورودی 12,000 نویسه فارسی و خروجی 2K تا 4K معمولاً منطقی است، اما برای مدل 8B فشار RAM قابل توجهی ایجاد می‌کند.
- انتخاب Q4_K_M برای شروع منطقی است. Q2/Q3 حجم کمتری دارند ولی افت کیفیت در ویرایش دقیق، رعایت JSON و حفظ نام‌ها معمولاً ارزش صرفه‌جویی محدود را ندارد.

اعداد RAM برآورد مهندسی‌اند، نه ادعای سازنده: اندازه وزن‌ها + KV cache در 12K + bufferهای اجرا + حاشیه Python/سیستم. مقدار دقیق به معماری CPU، batch و build کتابخانه وابسته است و باید از telemetry پنل اندازه‌گیری شود.

## 1. Gemma 3 4B IT Q4_K_M

Gemma 3 4B کوچک‌ترین گزینه‌ای است که هم کیفیت عمومی قابل قبول و هم توان چندزبانه جدی دارد. Google پشتیبانی بیش از 140 زبان، context ورودی 128K و کاربردهایی مانند خلاصه‌سازی را اعلام کرده است. در بنچمارک‌های منتشرشده مدل پایه 4B، امتیاز Global-MMLU-Lite برابر 57.0، WMT24++ برابر 48.4 و XQuAD برابر 68.0 گزارش شده است؛ این اعداد فارسی‌محور نیستند، اما ظرفیت چندزبانه مدل را تأیید می‌کنند.[^2]

نسخه GGUF سازمان `ggml-org` مستقیماً با llama.cpp معرفی شده و quant پیشنهادی Q4_K_M دارد.[^3] یک فهرست GGUF دیگر اندازه Q4_K_M را 2.490 GB و آن را نقطه متعادل کیفیت/حجم معرفی می‌کند.[^4]

**چرا برای این سرویس مناسب است:** اندازه آن تقریباً نصف Dorna 8B Q4 است، instruction following خوبی دارد و برای خلاصه‌سازی/بازنویسی طراحی شده است. ریسک اصلی این است که «پشتیبانی 140 زبان» تضمین کیفیت ویرایش فارسی نیست؛ تست روی نیم‌فاصله، اعداد فارسی، نام اشخاص و اصطلاحات سازمانی الزامی است.

### اطلاعات ثبت در پنل

- شناسه: `gemma-3-4b-it-q4_k_m`
- نام نمایشی: `Gemma 3 4B IT Q4_K_M`
- URL مستقیم: `https://huggingface.co/ggml-org/gemma-3-4b-it-GGUF/resolve/main/gemma-3-4b-it-Q4_K_M.gguf?download=true`
- نام فایل: `gemma-3-4b-it-Q4_K_M.gguf`
- اندازه: خالی بماند مگر مقدار دقیق از metadata همان revision استخراج شود.
- SHA-256: خالی نماند در استقرار تولید؛ پس از تثبیت revision از metadata مخزن دریافت و pin شود.
- توضیح: `مدل 4B چندزبانه، انتخاب متعادل برای اصلاح متن و صورت‌جلسه فارسی؛ حدود 5 تا 6GB RAM آزاد توصیه می‌شود.`

## 2. Qwen3 4B Q4_K_M

Qwen3 4B چهار میلیارد پارامتر، context بومی 32,768 توکن و GQA با 8 سر KV دارد. سازنده از پشتیبانی بیش از 100 زبان و گویش و بهبود instruction following خبر می‌دهد. نسخه رسمی GGUF یک فایل Q4_K_M حدود 2.5 GB دارد و Apache-2.0 است.[^5]

نکته تعیین‌کننده، دو حالت thinking و non-thinking است. Qwen صریحاً `/think` و `/no_think` را برای تغییر حالت معرفی می‌کند.[^6] برای اصلاح متن و صورت‌جلسه روی CPU، thinking معمولاً هزینه تولید توکن و latency را بالا می‌برد؛ بنابراین prompt این سرویس باید با `/no_think` شروع یا تمام شود. همچنین تنظیمات فعلی `temperature=.1/.2` با پیشنهاد رسمی Qwen3 برای non-thinking (`temperature=.7`, `top_p=.8`, `top_k=20`) تفاوت دارد. برای مقایسه عادلانه، ابتدا تنظیم فعلی را ثابت نگه دارید و سپس یک دور تنظیم اختصاصی Qwen انجام دهید.

### اطلاعات ثبت در پنل

- شناسه: `qwen3-4b-q4_k_m`
- نام نمایشی: `Qwen3 4B Q4_K_M`
- URL مستقیم: `https://huggingface.co/Qwen/Qwen3-4B-GGUF/resolve/main/Qwen3-4B-Q4_K_M.gguf?download=true`
- نام فایل: `Qwen3-4B-Q4_K_M.gguf`
- اندازه تقریبی: `2500000000` بایت؛ برای validation قطعی، مقدار دقیق metadata را جایگزین کنید.
- توضیح: `مدل 4B چندزبانه با کیفیت عمومی قوی؛ برای CPU باید حالت /no_think استفاده شود.`

## 3. Qwen2.5 3B Instruct Q4_K_M

این گزینه برای پایین آوردن فشار CPU/RAM و ساخت baseline سریع مناسب است. مخزن رسمی GGUF فایل تک‌تکه Q4_K_M با اندازه 2.10 GB دارد و اجرای llama.cpp را مستند کرده است.[^7] در عوض، شواهد فارسی هشدار می‌دهند که کوچک‌بودن مدل بی‌هزینه نیست: پژوهش ELAB گزارش می‌کند مدل‌های Qwen2.5 در اندازه 3B و 7B در برخی ارزیابی‌های alignment فارسی از بیشتر رقبا عقب بوده‌اند.[^8] این نتیجه به معنای نامناسب بودن برای تصحیح ASR نیست، اما مانع از انتخاب آن به‌عنوان مدل کیفی اصلی می‌شود.

### اطلاعات ثبت در پنل

## 4. Aya Expanse 8B Q4_K_M

Aya Expanse 8B تنها گزینه این shortlist است که مدل‌کارت آن فارسی را صریحاً یکی از 23 زبان هدف معرفی می‌کند. context آن 8K است.[^9] مدل‌کارت، ارزیابی چندزبانه در برابر Gemma 2 9B، Llama 3.1 8B، Ministral 8B و Qwen2.5 7B را نیز شرح می‌دهد. پژوهش فارسی ELAB نیز گزارش می‌کند Dorna2 در برخی دسته‌ها پشت Aya و Gemma قرار گرفته است؛ با توجه به تفاوت نسخه‌ها و benchmark، این شاهد جهت‌دهنده است نه حکم قطعی.[^8]

نسخه GGUF جامعه `bartowski` فایل تک‌تکه Q4_K_M با اندازه 5.06 GB دارد و با importance matrix کوانتیزه شده است.[^10] ضعف مهم مجوز `CC-BY-NC` و Acceptable Use Policy است: اگر سرویس درآمدزا یا سازمانی/تجاری است، بدون بررسی حقوقی نباید به تولید برود.

### اطلاعات ثبت در پنل

## مدل‌هایی که فعلاً پیشنهاد نمی‌شوند

- **Qwen2.5 7B رسمی Q4_K_M:** کیفیت بالقوه خوب، اما فایل رسمی دو تکه است و schema فعلی پنل فقط یک فایل می‌پذیرد.
- **Quantهای Q2_K و Q3_K:** کاهش RAM در برابر افت محسوس کیفیت و تبعیت از قالب؛ برای JSON تصحیح متن ریسک بالاتری دارند.
- **مدل‌های 1B تا 2B:** برای چت کوتاه خوب‌اند، ولی حفظ معنای متن طولانی، نام‌ها و استخراج action item معمولاً نقطه شکست آن‌هاست. فقط اگر سخت‌افزار زیر 6 GB RAM دارد، به‌عنوان tier اضطراری تست شوند.
- **Phi-4 Mini:** مدل 3.8B قدرتمندی است، اما شواهد مستقیم فارسی و مسیر GGUF رسمی/سازگار آن از چهار گزینه بالا ضعیف‌تر است؛ اولویت تست پایین‌تری دارد.
- **مدل‌های جدیدتر از Qwen3/Gemma3:** ممکن است روی کاغذ بهتر باشند، ولی سازگاری آن‌ها با نسخه pin‌شده `llama-cpp-python==0.3.16` باید پیش از توصیه عملی اثبات شود. ارتقای runtime یک پروژه جداگانه و نیازمند regression test است.

## طرح آزمایش پیشنهادی

یک مجموعه 60 نمونه‌ای از داده واقعی و بی‌نام‌شده بسازید:

- 20 متن کوتاه پرخطای ASR (زیر 300 واژه)
- 20 متن بلند جلسه (1,000 تا 3,000 واژه)
- 10 متن دارای نام شخص، شرکت، عدد، تاریخ و اصطلاح تخصصی
- 10 متن محاوره‌ای با نیم‌فاصله، واژه‌های انگلیسی و اعداد فارسی/لاتین

هر نمونه با Dorna Q4، Gemma 3 4B، Qwen3 4B، Qwen2.5 3B و در صورت مجاز بودن Aya اجرا شود. ترتیب اجرا تصادفی باشد و داور نام مدل را نبیند.

### معیارهای کیفیت

| معیار | وزن پیشنهادی | روش سنجش |
|---|---:|---|
| حفظ معنا و عدم hallucination | 30% | امتیاز انسانی 1 تا 5 |
| اصلاح نشانه‌گذاری و دستور فارسی | 20% | امتیاز انسانی + شمارش خطا |
| حفظ نام، عدد، تاریخ و اصطلاح | 20% | exact match / خطای بحرانی |
| کیفیت صورت‌جلسه و action item | 15% | completeness و عدم جعل مسئول/موعد |
| رعایت JSON در عملیات correction | 10% | درصد parse موفق بدون fallback |
| سبک و روانی فارسی | 5% | امتیاز انسانی 1 تا 5 |

### معیارهای کارایی

- peak RSS فرایند
- زمان load اولیه
- prompt processing tokens/sec
- generation tokens/sec
- latency کل p50 و p95
- درصد استفاده CPU و load average
- انرژی/دما، اگر میزبان telemetry آن را دارد
- نرخ خطا، تکرار و خروجی ناقص در سقف `max_tokens`

هر مدل حداقل 3 بار warm اجرا شود. امتیاز تصمیم‌گیری پیشنهادی:

`Final = 0.65 × Quality + 0.20 × normalized latency + 0.15 × normalized peak RAM`

برای محیط کم‌منبع می‌توان وزن RAM را به 0.25 و کیفیت را به 0.55 تغییر داد. مدل تولیدی باید علاوه بر امتیاز کل، حداقل 98% JSON معتبر و صفر تغییر بحرانی نام/عدد در مجموعه کنترل داشته باشد.

## تنظیمات اجرایی پیشنهادی

- `ASR_MAX_CONCURRENT=1` برای آزمایش و برای سرور CPU ضعیف.
- `ASR_CPU_THREADS` برابر تعداد هسته فیزیکی یا کمی کمتر؛ SMT را کورکورانه دو برابر نکنید.
- context را برای این کاربرد روی 8192 آزمایش کنید. کاهش از 12288 می‌تواند KV cache و فشار RAM را کم کند، به شرط آنکه prompt + output جا شود.
- برای Qwen3، `/no_think` را به instruction اضافه کنید.
- برای correction، grammar/JSON schema در llama.cpp از prompt-only مطمئن‌تر است؛ llama.cpp امکان محدودکردن خروجی با JSON schema را دارد.[^11] wrapper فعلی از این قابلیت استفاده نمی‌کند و افزودن آن می‌تواند نرخ JSON معتبر را بهبود دهد.
- مدل‌ها را یکی‌یکی نصب و warm کنید؛ cache فعلی فقط یک LLM دارد، بنابراین مقایسه چندمدلی شامل هزینه reload خواهد بود.
- URLهای `main` برای آزمایش راحت‌اند ولی immutable نیستند. پس از انتخاب مدل، revision را pin، اندازه دقیق و SHA-256 را ثبت کنید.

## تصمیم نهایی پیشنهادی

اگر فقط دو مدل می‌خواهید: **Gemma 3 4B Q4_K_M** و **Qwen3 4B Q4_K_M**.

اگر کمترین فشار اولویت مطلق است: **Qwen2.5 3B Q4_K_M** را baseline قرار دهید، ولی تا عبور از تست حفظ نام/عدد و JSON آن را پیش‌فرض نکنید.

اگر بهترین فارسی ممکن در محدوده 8B را می‌خواهید و استفاده غیرتجاری است: **Aya Expanse 8B Q4_K_M** را کنار Dorna Q4 مقایسه کنید. برای استفاده تجاری، Gemma/Qwen با شرایط مجوز مناسب‌تر، یا یک مدل فارسی دارای مجوز تجاری روشن، انتخاب امن‌تری است.
