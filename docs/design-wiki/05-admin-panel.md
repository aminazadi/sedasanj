# ۰۵ — پنل ادمین (اپراتور و کارکنان پلتفرم)

**هدف:** مرجع دقیق برای طراح یا ابزار هوش مصنوعی (Claude Design) تا پنل ادمین صداسنج را پروتوتایپ کند. این صفحه می‌گوید پنل **امروز** چه صفحه‌ها، جدول‌ها، فیلترها، عمل‌ها و حالت‌هایی دارد (از کد خوانده شده) و **کجا** بازطراحی می‌تواند چیزی اضافه کند. بازیگران پنل کارکنان خود صداسنج هستند، نه مشتری: `super_admin` («مدیر کل») و `support` («پشتیبانی»).

**راهنمای برچسب‌ها**

| برچسب | معنی |
|---|---|
| «موجود» | امروز در کد هست (مسیر و رفتار از فایل خوانده شده) |
| «جدید» | در بازطراحی پیشنهاد می‌شود؛ در کد نیست |
| «⚠ نیازمند تأیید» | در کد تأیید نشد، یا به تصمیم محصول/لابراتوار وابسته است |

قراردادها: شناسه، مسیر، فایل، کد خطا، مقدار enum و نام کامپوننت انگلیسی و داخل بک‌تیک (LTR، ارقام لاتین) است؛ متن رابط فارسی و ارقام فارسی. هیچ کلید، رمز یا توکنی در این سند نیست و در نمونه‌ها هم نباید بیاید.

## ۲. ماتریس نقش‌ها

**اصل:** سرور حقیقت است. `StaffDep` = هر کارمند فعال؛ `SuperAdminDep` = فقط `super_admin` (پاسخ `forbidden`، ۴۰۳). رابط امروز **فقط دو آیتم منو** را برای `support` پنهان می‌کند؛ بقیهٔ صفحه‌ها و دکمه‌ها برای هر دو نقش یکسان نمایش داده می‌شوند و عمل ممنوع بعد از تلاش با خطا رد می‌شود. «جدید»: دکمه‌های ممنوع برای `support` غیرفعال (با توضیح «فقط مدیر کل») یا پنهان باشند، و بالای صفحه نشان «حالت فقط‌خواندنی» بیاید.

|---|---|---|---|
| خواندن همهٔ فهرست‌ها (سازمان‌ها، کارها، outbox، ممیزی، سفارش‌ها، پرداخت‌ها، اشتراک‌ها، سرنخ‌ها، نصب‌ها، نسخه‌ها، ناوگان، تنظیمات، راهنما) | بله | بله | `StaffDep` در همهٔ `GET` |

### ۳.۲ الگوی هدف (جدید)

یک مودال واحد `ConfirmActionDialog` با **سه سطح**، که جای `prompt/confirm` را بگیرد:

| سطح | چه زمانی | محتوای مودال |
|---|---|---|
| ۱ — تأیید ساده | عمل برگشت‌پذیر و کم‌اثر (تغییر وضعیت سرنخ) | جملهٔ اثر + دو دکمه |
| ۲ — دلیل | تغییر اثرگذار روی یک سازمان یا مالی (اجرای مجدد کار، تعلیق، شارژ دستی، ابطال سفارش، اقدام اشتراک) | جملهٔ اثر با نام سازمان، `دلیل` (≥۳ نویسه)، نمایش «چه چیزی در گزارش رویدادها ثبت می‌شود» |
| ۳ — دلیل + هویت | اثر روی همهٔ مشتریان یا برگشت‌ناپذیر (انتشار نسخه، پوش سراسری، بازپرداخت، مدیریت کاربران ادمین، مهاجرت/بازگشت دیتابیس، تنظیمات سامانه/درگاه) | سطح ۲ + `گذرواژهٔ فعلی` + `کد دومرحله‌ای` (اجباری اگر حساب TOTP دارد؛ در UI امروز اختیاری و سرور تصمیم می‌گیرد) |

قواعد ظاهر: عنوان عمل، **اثر دقیق** (چند سازمان/چند اشتراک، مثل «۱۲ اشتراک به این نسخه وصل است»)، دکمهٔ تأیید با فعل مشخص (نه فقط «تأیید»)، دکمهٔ مخرب قرمز با رنگ + آیکن، پس از شکست پیام فارسی با اقدام بعدی و حفظ فیلدها (به‌جز رمز). خطاهای `unauthorized` («رمز یا کد دومرحله‌ای درست نیست») و `forbidden` («فقط مدیر ارشد…») در `jalaseNegarErrors.ts`/`mlModelErrors.ts` متن آماده دارند. ⚠ سرور برای `unauthorized` هم رمز غلط و هم نشست منقضی را یک کد می‌دهد؛ UI امروز با جست‌وجوی «password/two-factor» در پیام فرق می‌گذارد.

| ۱۰۲۴ (تبلت افقی) | **منوی ثابت ۲۸۸px ظاهر می‌شود** (`lg`) | ۱۰۲۴ − ۲۸۸ − ۶۴ = **۶۷۲px** | **بدترین حالت امروز**: محتوا از حالت ۷۶۸ باریک‌تر است |
| ۱۲۸۰ | منوی ثابت | ۱۲۸۰ − ۲۸۸ − ۶۴ = **۹۲۸px** | جدول‌های تا ۷ ستون جا می‌شوند |
| ۱۴۴۰ | منوی ثابت | ۱۴۴۰ − ۲۸۸ − ۶۴ = **۱۰۸۸px** | حالت مرجع طراحی (سقف ۱۶۰۰ هنوز فعال نشده) |

**«جدید» — پیشنهاد:** از ۱۰۲۴ تا ۱۲۷۹ منو به **ریل آیکنی ۷۲px** (با tooltip و باز شدن موقت) کوچک شود تا عرض محتوا ≥ ۸۸۰px بماند؛ ≥ ۱۲۸۰ منوی کامل. در ۷۶۸ همان drawer.

## ۶. واژگان وضعیت (فرهنگ لغت یکپارچه)

مرجع یک‌جا برای نشان‌ها. «امروز» = برچسب موجود در رابط؛ «پیشنهاد» = برچسب فارسی برای مقادیری که امروز خام نمایش داده می‌شوند (⚠ نیازمند تأیید متن).

| حوزه | مقدار ← برچسب |
|---|---|
| **سازمان** | `active` فعال (امروز)؛ `suspended` معلق (امروز)؛ پیشنهاد: `pending` در انتظار، `provisioning` در حال آماده‌سازی، `maintenance_readonly` نگهداری (فقط‌خواندنی)، `migration_failed` شکست مهاجرت |
| **کار** | `queued` در صف، `running` در اجرا، `succeeded` موفق، `failed_retryable` خطای موقت، `failed_terminal` خطای نهایی (امروز، فقط در فیلتر)؛ نوع: `asr`, `emotion`, `correction`, `llm`, `notify` (امروز خام) |
| **اشتراک** | `active` فعال، `trialing` آزمایشی، `pending_payment` در انتظار پرداخت، `expired` منقضی، `canceled` لغوشده؛ «مهلت» محاسبه‌ای (ذخیره نمی‌شود) |
| **پلن (نسخه)** | `draft` پیش‌نویس، `published` منتشرشده، `retired` بازنشسته |
| **سفارش** | `draft` پیش‌نویس، `pending_payment` در انتظار پرداخت، `paid` پرداخت‌شده، `canceled` لغوشده، `partially_refunded` بازپرداخت جزئی، `refunded` بازپرداخت‌شده |
| **تلاش پرداخت** | `redirected` هدایت‌شده، `pending_verification` نیازمند بررسی، `verified` تأییدشده (برای ملت «ستل‌نشده» تا ثبت ستل)، `failed` ناموفق، `canceled` لغوشده، `expired` منقضی‌شده (بعد از ۲ ساعت بی‌پاسخ)، `superseded` جایگزین‌شده |
| **بازپرداخت** | `pending`, `completed` تکمیل‌شده, `failed`؛ روش: `reverse` ریورس درگاه، `manual` دستی |
| **نصب** | `requested` درخواست‌شده، `paid` پرداخت‌شده، `reviewing` در بررسی، `scheduled` زمان‌بندی‌شده، `in_progress` در حال اجرا، `completed` تکمیل‌شده، `canceled` لغوشده |
| **سرنخ** | `new` جدید، `contacted` تماس گرفته شد، `qualified` واجد شرایط، `closed` بسته |
| **نسخهٔ ماژول / جلسه‌نگار** | `draft` پیش‌نویس، `published` منتشرشده، `revoked` لغوشده؛ کانال `stable` پایدار / `beta` آزمایشی |
| **اهمیت نسخه** | `normal` عادی، `recommended` توصیه‌شده، `critical` مهم، `security` امنیتی |
| **به‌روزرسانی سرور** | `started` در حال اجرا، `succeeded` موفق، `failed` ناموفق، `rolled_back` بازگردانی شد |
| **مدل یادگیری** | `uploading` در حال آپلود، `ready` آماده، `revoked` باطل‌شده، `deleted` فایل حذف‌شده؛ کانال `latest`/`champion` |
| **دیتابیس سازمان** | `provisioning`, `ready`, `maintenance`, `quarantined`, `failed` (امروز خام)؛ پیشنهاد: در حال ساخت، آماده، نگهداری، قرنطینه، ناموفق |
| **کار تأمین دیتابیس** | `pending`, `running`, `retryable`, `failed`, `succeeded` |
| **پیامد پوش** | `queued` در صف، `sending` در حال ارسال، `accepted` پذیرفته‌شده توسط Firebase، `failed` ناموفق، `cancelled` لغوشده، `unknown` نامشخص |
| **مقاله راهنما** | `draft` پیش‌نویس، `published` منتشرشده؛ نوع `article` مقاله، `error` خطا، `faq` پرسش متداول |
| **شدت کد خطا** | `info` اطلاع، `warning` هشدار، `error` خطا، `critical` بحرانی |
| **ورود دومرحله‌ای** | فعال / غیرفعال |

## ۸. جمع‌بندی برای پروتوتایپ

1. **پوسته:** منوی راست ۲۸۸px با هشت گروه؛ drawer زیر ۱۰۲۴؛ نوار بالای ۶۴px؛ منوی «ریل» پیشنهادی ۱۰۲۴–۱۲۷۹.
2. **نقش:** `support` همه‌چیز را می‌خواند و عملیات روزمره (کار، اشتراک، سفارش، پرداخت، سرنخ، نصب) را انجام می‌دهد؛ مدیر کل تنها کسی است که پول، نسخه، کاربر، تنظیمات و پوش را تغییر می‌دهد. هر دکمهٔ «فقط مدیر کل» برای `support` غیرفعال + توضیح.
3. **تأیید:** سه سطح یکپارچه (ساده / دلیل / دلیل + رمز + TOTP) جای `prompt`/`confirm` را می‌گیرد.
4. **جدول:** سه تراکم، ستون هویت ثابت، ستون عمل ثابت، کشوی جزئیات، فیلتر در URL، اسکلت هم‌شکل.
5. **سفر عیب‌یابی:** داشبورد ← کارها/outbox ← سازمان ← عمل ← ممیزی، با ستون سازمان و تب‌های پردازش/رویداد در جزئیات سازمان.
6. **داده‌های نمونه:** ساختگی و بی‌هویت (`09-sample-data-and-copy.md`)؛ هیچ کلید یا رمزی نمایش داده نشود؛ شناسه‌ها و `SHA-256` تصادفی و کوتاه.
